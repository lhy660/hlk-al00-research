# 2026-11-10 `su -c` 中 mount 找不到：根因复现与修复验证

设备 MGFVB19B13014705 / HLK-AL00。新 APK `fa8247a392abef1af2ea3392006750eb`
按 `reboot → install → reboot → 400 s 门` 部署后，以下为**重启态**验收。
详细机制见 `hlk-root-dist/docs/RESEARCH_LOG.md` §42。

## 1. 根因（修复前逐字复现）

真机 Termux 进程（pid 22496 / 22497）environ：

    PATH=/data/data/com.termux/files/usr/bin

`$PREFIX/bin/` 下 `mount` / `umount` / `toybox` 全部 MISSING；
`mkdir` / `chroot` 是 coreutils 链接（所以截图里 mkdir 能成功）。
`hlk_su` 用绝对路径 `execv("/system/bin/sh")` 且原样继承 environ，
因此那个 sh 的 PATH 仍是 Termux 的。

    PATH=$PREFIX/bin:$PREFIX/bin/applets /data/local/tmp/hlk_su -c "mount --help"
    -> /system/bin/sh: mount: inaccessible or not found

与用户截图逐字一致。截图里 `bash: /dev/null: 权限不够` 是连带后果：
`su -c "mount ..."` 全部失败 → `/dev` 未 bind → rootfs 里的 `/dev/null`
只是一个 `-rw------- 0 字节` 普通文件（实测）。

## 2. 修复后（重启态，模拟 Termux PATH 走 `su -c`）

    PATH=/data/data/com.termux/files/usr/bin:/sbin:...:/system/bin:...:/vendor/xbin
    mount  -> /system/bin/mount
    umount -> /system/bin/umount
    MOUNT_RC=0
    tmpfs /dev/hlk-final tmpfs rw,seclabel,relatime 0 0
    UMOUNT_RC=0

## 3. `sudo su -c` 形式（第三方启动脚本常用）

    /system/bin/mount
    usage: mount [-afFrsvw] [-t TYPE] [-o OPTION,] [[DEVICE] DIR]
    RC=0

## 4. 自动部署脚本（marker → cmp 内容比对）

    1st run: patched /data/data/com.termux/files/usr/bin/su
             grant_su: uid=10161 allow_su=1 key=com.termux OK
             TERMUX-SETUP-OK uid=10161
    2nd run: (无 patched 行)
             TERMUX-SETUP-OK uid=10161

## 5. 受控挂载链（隔离 mnt ns 内，退出零残留）

    bind /dev        rc=0      proc        rc=0
    sysfs            rc=0      devpts      rc=0
    tmpfs /dev/shm   rc=0
    /dev/null  -> crw-rw-rw- 1 root root 1, 3
    chroot + bash    CONTAINER_OK / DEVNULL_WRITE_OK
    系统挂载表：clean，无残留进程

第三方启动脚本整体放入隔离 mnt ns 跑过一次，能一路走到最后的 chroot
步骤，不再出现 `mount: inaccessible or not found`。
